## 1. 문제 설명

문자열 `my_string`과 두 정수 `m`, `c`가 주어진다.

문자열을 한 줄에 `m`글자씩 가로로 적었을 때, 왼쪽부터 세로로 `c`번째 열에 적힌 글자들을 순서대로 이어 붙여 반환한다.

### 예시

**입력**

```javascript
my_string = "abcdefg"
m = 4
c = 2
```

문자열을 4글자씩 나누면 다음과 같다.

```text
abcd
efg
```

두 번째 열에 있는 글자를 위에서 아래로 읽으면 `b`, `f`이므로 결과는 `"bf"`이다.

다른 예시로 `"programmers"`를 3글자씩 나누고 두 번째 열을 읽으면 다음과 같다.

```text
pro
gra
mme
rs
```

두 번째 열의 글자는 `r`, `r`, `m`, `s`이므로 결과는 `"rrms"`이다.

---

## 2. 처음 생각한 풀이

처음에는 문자열을 `m`글자씩 끊어서 배열에 저장한 다음, 각 문자열에서 `c`번째 문자를 가져오면 된다고 생각했다.

예를 들어 `"programmers"`를 3글자씩 나누면 다음과 같다.

```text
pro
gra
mme
rs
```

각 문자열의 두 번째 문자를 가져오면 `r`, `r`, `m`, `s`가 된다. 이 문자들을 하나의 문자열로 합치면 정답을 구할 수 있다.

이 과정을 두 단계로 나눠서 구현하기로 했다.

1. 문자열을 `m`글자씩 잘라 배열에 저장한다.
2. 배열을 순회하면서 각 문자열의 `c`번째 문자를 결과 문자열에 추가한다.

두 작업은 순서대로 실행되기 때문에 중첩 반복문을 사용할 필요가 없다.

## 3. 정답 코드

```javascript
function solution(str, m, c) {
    let answer = '';
    let strArr = [];

    for (let i = 0; i <= str.length - m; i += m) {
        strArr.push(str.substr(i, m));
    }

    for (let i = 0; i < strArr.length; i++) {
        answer += strArr[i][c - 1];
    }

    return answer;
}
```

### 코드 설명

**첫 번째 반복문**

```javascript
for (let i = 0; i <= str.length - m; i += m) {
    strArr.push(str.substr(i, m));
}
```

문자열의 시작 인덱스를 `m`만큼 증가시키면서 최대 `m`개의 문자를 가져와 배열에 저장한다.

예를 들어 `str`이 `"abcdefg"`이고 `m`이 4라면 `"abcd"`와 `"efg"`를 가져오게 된다. 다만 현재 코드의 조건에서는 길이가 `m`보다 짧은 마지막 문자열은 배열에 저장되지 않는다.

**두 번째 반복문**

```javascript
for (let i = 0; i < strArr.length; i++) {
    answer += strArr[i][c - 1];
}
```

배열에 저장된 문자열을 하나씩 확인하면서 `c`번째 문자를 가져온다.

문자열의 인덱스는 0부터 시작하기 때문에 `c`번째 문자에 접근하려면 `c - 1`을 사용해야 한다. 가져온 문자는 `answer`에 차례대로 추가한다.

## 4. 시간 복잡도 분석

문자열의 길이를 `n`이라고 하자.

### 첫 번째 반복문

반복문에서 `i`는 한 번 실행될 때마다 `m`씩 증가한다.

따라서 문자열을 나누는 횟수는 대략 문자열 길이를 `m`으로 나눈 값이다.

### 두 번째 반복문

두 번째 반복문은 첫 번째 반복문에서 만들어진 배열의 길이만큼 실행된다. 배열에는 문자열을 `m`글자씩 나눈 결과가 들어 있으므로, 이 반복문 역시 대략 문자열 길이를 `m`으로 나눈 횟수만큼 실행된다.

### 전체 시간 복잡도

두 반복문은 중첩되어 있지 않고 순서대로 실행된다. 따라서 각 반복문의 실행 비용을 더해서 분석하면 된다.
반복 횟수만 기준으로 보면 두 반복문 모두 대략 문자열 길이를 `m`으로 나눈 횟수만큼 실행되므로 전체 반복 횟수도 같은 수준이다.

여기서 중요한 점은 `m`을 어떻게 취급하느냐에 따라 표현이 달라진다는 것이다.

- `m`이 항상 10이나 100처럼 고정된 값이라면 시간 복잡도는 `O(n)`이다.
- `m`이 입력값이고 문자열 길이에 따라 함께 커질 수 있다면 반복 횟수는 `n / m`의 영향을 받는다.

예를 들어 문자열 길이가 1,000,000으로 같더라도 `m`이 10일 때와 10,000일 때는 반복 횟수가 크게 달라진다.
다만 실제 실행 비용을 엄밀하게 계산할 때는 문자열을 자르는 작업과 `answer`에 문자를 이어 붙이는 작업도 고려해야 한다.
위의 분석은 반복 횟수를 중심으로 살펴본 것이다.

## 5. 정리

이번 문제를 풀면서 확인한 내용은 다음과 같다.

- 반복문이 두 개라고 해서 시간 복잡도가 무조건 `O(n²)`이 되는 것은 아니다.
- 중첩 반복문이 아니라 순차적으로 실행된다면 각 반복문의 실행 비용을 더해서 계산한다.
- 반복문이 얼마나 자주 실행되는지는 증감식에 따라서도 달라진다.
- 시간 복잡도를 분석할 때는 반복 횟수뿐 아니라 반복문 안에서 실행하는 작업도 살펴봐야 한다.

**면접에서 설명한다면**

이 코드는 문자열을 `m`글자씩 나누는 반복문과 각 조각에서 `c`번째 문자를 추출하는 반복문으로 구성되어 있습니다. 두 반복문은 중첩되어 있지 않으며, 각각 대략 문자열 길이를 `m`으로 나눈 횟수만큼 실행됩니다. 따라서 반복 횟수 기준으로는 `O(n / m)`으로 볼 수 있고, `m`이 상수라면 `O(n)`으로 표현할 수 있습니다.

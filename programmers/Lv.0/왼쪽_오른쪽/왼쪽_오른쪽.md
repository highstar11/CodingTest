## 1. 문제 설명

문자열 리스트 `str_list`에는 `"u"`, `"d"`, `"l"`, `"r"` 네 개의 문자열이 여러 개 저장되어 있다.

`str_list`에서 `"l"`과 `"r"` 중 먼저 나오는 문자열을 기준으로 배열을 잘라 반환하는 문제이다.

- `"l"`이 먼저 나오면 `"l"`의 왼쪽에 있는 문자열들을 반환한다.
- `"r"`이 먼저 나오면 `"r"`의 오른쪽에 있는 문자열들을 반환한다.
- `"l"`이나 `"r"`이 없다면 빈 배열을 반환한다.

예를 들어 `["u", "u", "l", "r"]`이 주어지면 `"l"`의 왼쪽에 있는 `["u", "u"]`를 반환한다.

반면 `["l"]`이 주어지면 `"l"`의 왼쪽에 있는 원소가 없으므로 빈 배열을 반환한다.

## 2. 설계 과정

처음에는 `forEach()`를 사용해서 배열을 순회하면서 `"l"`이나 `"r"`을 찾고, 해당 위치를 기준으로 `slice()`를 사용해 배열을 자르는 방식으로 접근했다.

`"l"`을 만나면 해당 인덱스의 왼쪽을 반환하고, `"r"`을 만나면 해당 인덱스의 오른쪽을 반환하면 된다고 생각했다.

하지만 작성한 코드에는 문제가 있었다.

`forEach()` 내부에서 `return`을 사용하더라도 반복문 전체가 종료되지 않는다는 점이다. 콜백 함수 내부의 `return`은 해당 콜백 함수의 실행만 종료한다. 따라서 반복을 중단하거나 함수의 결과를 반환하는 용도로 사용하기에는 적절하지 않았다.

이후 일반적인 `for`문으로 변경했다. `for`문에서는 `"l"`이나 `"r"`을 발견했을 때 `return`을 사용하면 `solution()` 함수 자체를 종료하면서 결과를 반환할 수 있다.

다만 처음 작성한 `for`문에도 문제가 있었다. 반복문 내부에서 `"l"`이나 `"r"`을 찾지 못했을 때 빈 배열을 반환하도록 작성했는데, 이 코드가 첫 번째 원소를 확인한 직후 실행되기 때문에 나머지 원소를 확인하지 못했다.

따라서 빈 배열을 반환하는 처리는 반복문이 모두 끝난 뒤에 작성해야 한다.

## 3. 정답 코드

```javascript
function solution(str_list) {
    for (let i = 0; i < str_list.length; i++) {
        if (str_list[i] === "l") {
            return str_list.slice(0, i);
        }

        if (str_list[i] === "r") {
            return str_list.slice(i + 1);
        }
    }

    return [];
}
```

## 4. 코드 설명

`for`문을 사용해 배열의 첫 번째 원소부터 순서대로 확인한다.

먼저 현재 원소가 `"l"`인지 확인한다.

`"l"`이라면 `slice(0, i)`를 사용해 배열의 처음부터 현재 인덱스 직전까지의 원소를 반환한다. `slice()`의 두 번째 인수는 포함되지 않기 때문에 `"l"` 자체는 결과에 포함되지 않는다.

반대로 현재 원소가 `"r"`이라면 `slice(i + 1)`을 사용한다. 시작 인덱스를 `"r"`의 다음 위치로 설정하고 마지막 인수를 생략하면 배열의 끝까지 원소를 가져올 수 있다.

이때 `return`을 사용하기 때문에 `"l"`이나 `"r"` 중 먼저 발견한 문자를 기준으로 결과를 반환하고 함수가 종료된다.

반복문이 끝날 때까지 `"l"`과 `"r"`을 발견하지 못했다면 빈 배열을 반환한다.

## 5. 시간 복잡도 분석

배열을 처음부터 순회하면서 `"l"`이나 `"r"`을 찾기 때문에 최악의 경우 배열의 모든 원소를 확인해야 한다.

배열의 길이가 길어질수록 확인해야 하는 원소의 수도 증가하므로 시간 복잡도는 O(n)이다.

다만 `"l"`이나 `"r"`이 앞부분에 있다면 모든 원소를 확인하지 않고도 종료할 수 있다.

`slice()`는 결과 배열을 생성하면서 선택한 원소들을 복사하기 때문에, 반환하는 배열의 길이에 비례하는 추가 작업도 발생한다. 이 부분에 대해서는 학습이 더 필요할 것 같다.

## 6. 정리

이번 문제에서는 배열을 순회하는 방법과 `slice()`의 사용법을 다시 확인할 수 있었다.

특히 `forEach()` 내부에서 `return`을 사용한다고 해서 반복문 전체가 종료되는 것은 아니라는 점을 배웠다. 반복을 중단하거나 특정 조건에서 함수의 결과를 즉시 반환해야 한다면 일반적인 `for`문을 사용하는 것이 더 적절할 수 있다.

또한 `slice()`는 두 번째 인덱스에 해당하는 원소를 포함하지 않는다는 점도 중요하다. 시작 인덱스만 전달하면 해당 위치부터 배열의 끝까지 가져올 수 있다.

마지막으로 반복문 내부에 `return []`을 작성하면 조건을 만족하는 원소를 찾기 전에 함수가 종료될 수 있다는 점을 확인했다. 반복문이 끝난 뒤 빈 배열을 반환하도록 작성해야 `"l"`과 `"r"`이 없는 경우를 올바르게 처리할 수 있다.

단순한 배열 문제이지만, 반복문의 실행 흐름과 함수의 반환 시점, 배열 메서드의 동작 방식을 함께 이해할 수 있었던 문제였다.
